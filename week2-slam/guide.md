# TurtleBot3 Nav2 실습 안내

TurtleBot3 Burger가 제공된 지도에서 자신의 위치를 추정하고, 지정한 목표 지점까지 자율주행하는 시뮬레이션 실습입니다. 지도, 센서 데이터, 좌표계, 계획 경로와 이동 명령이 어떻게 연결되는지 확인합니다.

## 실행 환경

| 항목 | 기준 |
| --- | --- |
| 운영체제 | Ubuntu 24.04 LTS |
| ROS 2 | Jazzy Jalisco |
| Nav2 | 1.3.13 기준 |
| 시뮬레이터 | Gazebo Harmonic, Gazebo Sim 8.x |
| 로봇 | TurtleBot3 Burger, 좌우 바퀴를 사용하는 차동 구동 |
| 시각화 도구 | RViz 2 |

Gazebo는 로봇의 움직임과 센서를 시뮬레이션하고, ROS 2는 각 노드 사이에서 데이터를 전달합니다. Nav2가 자율주행을 수행하며 RViz는 지도와 로봇 상태를 보여 줍니다. 시간 기준은 Gazebo가 발행하는 `/clock`으로 통일합니다.

## 탑재 센서

| 센서 | 주요 설정 | 용도 |
| --- | --- | --- |
| 기본 2D 라이다 | 수평 360개 샘플, 5 Hz, 측정 범위 0.12–3.5 m | 지도와 스캔을 비교한 위치 추정, 주변 장애물 감지 |
| 추가 3D 라이다 | 수평 720개 × 수직 16채널, 10 Hz, 측정 범위 0.10–20 m | 벽·기둥 등 주변 구조물의 높이를 포함한 점군 관찰 |
| IMU | 200 Hz, 자세·3축 각속도·3축 선형가속도 | 로봇의 회전과 가속도 데이터 확인 |

3D 라이다는 수평 0.5° 간격으로 한 바퀴를 스캔하고, 수직 방향은 -15°부터 +15°까지 측정합니다. 특정 제품을 그대로 재현한 모델이 아닌 범용 16채널 시뮬레이션 센서입니다. 센서 주파수는 시뮬레이션 시간 기준 설정값이며 실제 수신 속도는 PC 부하에 따라 달라질 수 있습니다.

현재 자율주행에는 **2D 스캔과 odometry**를 사용합니다. 3D 점군과 IMU 데이터도 발행하지만, 3D 점군을 Nav2 장애물 지도에 넣거나 IMU를 위치 추정 필터에 융합하는 구성은 포함하지 않습니다.

## 주요 토픽

토픽은 ROS 2 노드가 데이터를 주고받는 이름입니다. 같은 데이터를 연결하려면 토픽명과 메시지 타입이 맞아야 합니다.

| 토픽 | 메시지 타입 | 내용 |
| --- | --- | --- |
| `/clock` | `rosgraph_msgs/msg/Clock` | 시뮬레이션 시간 |
| `/scan` | `sensor_msgs/msg/LaserScan` | 2D 라이다 거리 측정 |
| `/points` | `sensor_msgs/msg/PointCloud2` | 높이를 포함한 3D 점군 |
| `/imu` | `sensor_msgs/msg/Imu` | 자세, 각속도, 선형가속도 |
| `/odom` | `nav_msgs/msg/Odometry` | 로봇의 이동 위치와 속도 추정 |
| `/map` | `nav_msgs/msg/OccupancyGrid` | 제공된 공간의 점유 지도 |
| `/plan` | `nav_msgs/msg/Path` | 목표까지의 전역 계획 경로 |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 로봇에 전달하는 최종 선속도·각속도 명령 |
| `/tf`, `/tf_static` | `tf2_msgs/msg/TFMessage` | 좌표계 사이의 변환 관계 |

Gazebo의 3D 점군 토픽 `/lidar_3d/points`는 브리지를 통해 ROS 2의 `/points`로 전달됩니다. 목표 위치와 방향은 `/navigate_to_pose` action으로 보내며, 주행 중 피드백과 최종 성공·실패 결과를 받을 수 있습니다.

## 지도·위치 추정·경로 계획

제공된 지도는 sandbox 월드에 대응하는 2D 점유 지도이며, 해상도는 0.05 m/pixel입니다. RViz의 기본 지도 색상에서 흰색은 빈 공간, 검은색은 장애물, 회색은 아직 알 수 없는 영역을 나타냅니다.

AMCL은 지도와 2D 라이다 측정을 비교해 로봇의 위치를 추정합니다. 이 실습은 저장된 지도를 사용하므로 새 지도를 만드는 SLAM 단계는 실행하지 않습니다. costmap은 지도와 센서 정보를 바탕으로 장애물 주변에 이동 비용을 부여해 로봇이 통과할 공간을 판단하도록 돕습니다.

목표가 들어오면 NavFn이 전역 경로를 계획하고, MPPI가 경로를 따라갈 속도를 계산합니다. 이 명령은 velocity smoother와 collision monitor를 거쳐 최종 `/cmd_vel`로 전달됩니다. 경로가 화면에 나타나는 것과 로봇이 실제로 목표에 도착하는 것은 각각 확인해야 합니다.

## TF와 RViz에서 확인할 내용

주요 TF 연결은 `map → odom → base_footprint → base_link → 센서 링크`입니다. `map`은 지도 기준, `odom`은 연속적인 이동 기준, `base_link`는 로봇 몸체 기준입니다. 센서 프레임은 2D 라이다의 `base_scan`, 3D 라이다의 `lidar_3d_link`, IMU의 `imu_link`로 구분합니다.

TF는 센서가 측정한 점을 지도 위 어느 위치에 표시할지 결정하는 데 필요합니다. RViz의 Fixed Frame을 `map`으로 두고 로봇 모델과 스캔이 지도에 맞게 겹치는지 확인합니다. 3D 점군은 높이에 따라 색을 달리하고 비스듬한 Orbit 시점에서 보면 수직 구조를 구분하기 쉽습니다.

## 실습 순서

1. 시뮬레이션과 Nav2를 실행하고 지도·로봇·센서 데이터가 표시되는지 확인합니다.
2. 시작 위치와 라이다 스캔이 지도에 맞는지 확인합니다. 필요하면 RViz의 **2D Pose Estimate**로 초기 위치와 방향을 지정합니다. 이 기능은 위치 추정값을 설정하며 로봇을 순간이동시키지는 않습니다.
3. **Nav2 Goal**이나 action 클라이언트로 빈 공간의 목표 위치와 도착 방향을 지정합니다.
4. 전역 경로와 실제 이동을 함께 관찰하고, 주변 장애물에 따라 경로와 속도가 어떻게 바뀌는지 확인합니다.
5. 최종 action 결과가 `SUCCEEDED`인지 확인하고 목표 지정부터 도착까지의 영상과 지도·계획 경로가 보이는 RViz 화면을 기록합니다.
